## 0. 生成时先选镜头

两套镜头都可以用，按这次要的画面选，不要默认死锁其中一套。

| 选项 | 什么时候用 | 画面 |
| --- | --- | --- |
| 0 透视俯视 | 要正上方、边线不汇聚的像素素材 | 正交，没有近大远小 |
| 约 20° 轻俯视 | 要看见少量顶面，同时保留正面信息 | 原指南的 20–35°、弱透视、近似正交 |

同一张 Sheet、同一套要拼在一起的资产，只锁一种。换一批可以换镜头。两种都不要做成 45° 等距、完全正视、电影广角或强透视。

风格两边相同：干净型高清像素，大色块、低纹理、清晰轮廓、中低细节、柔和明暗。不要做成低分辨率复古颗粒像素。

### 0.1 选 0 透视时

- 相机在正上方，正交投影。平行线保持平行，没有消失点。
- 同一类物件放在画面任何位置，宽高和顶面比例都相同。
- 0 透视里再分两种，这一批只锁一种：纯顶视（几乎只有顶面，适合地砖和平面标记），或正交俯视带正面（顶面加一段不汇聚的正面，适合家具、道具、墙段）。

尺寸表里的「高」是轻俯视画面的竖向像素（成年人站立约 180px）。0 透视这一批改成对照占地（宽 × 深）和顶面比例，角色参照用一张固定的俯视剪影。分级区间仍然表示「在世界里有多大」。先做大母版，再缩小；最终 PNG 进引擎保持 Scale = 1。

### 0.2 选约 20° 时

用原指南规则：约 20–35° 轻俯视，弱透视，近似正交。能看见少量地面和家具顶部，近处和远处尺寸差很小。尺寸表按站立身高和画面高度来读，成年人基准约 180px。模板用第 6 节的 20–35° 版本，或下面这一份。

### 0.3 直接复制的模板

每次只改 `[ASSETS]`，并先选好 CAMERA。失败时只改对应区块，不要整段重写。STYLE、LAYOUT、BACKGROUND 两边共用；LIGHTING 不要脚下接触影和地面椭圆影。

**0 透视俯视（带正面）：**

```text
[STYLE]
clean high-resolution pixel-inspired 2D game assets; large color blocks; low texture; clean dark outlines; clear readable silhouettes; controlled medium-low detail density; soft value transitions; no grain or weathering

[CAMERA]
strict top-down orthographic view; zero perspective; 90-degree overhead camera; parallel edges; no vanishing point; no foreshortening; visible top face plus a short parallel front face; consistent footprint; not 20-35 degree elevated view; not three-quarter view; not 45-degree isometric; not front view

[LIGHTING]
soft even lighting; keep only internal structural shading and self-occlusion; no cast ground shadows; no contact shadows; no environmental shadows

[ASSETS]
8-12 isolated assets from one category: [REPLACE THIS LIST ONLY]

[LAYOUT]
isolated objects; generous spacing; no touching; no overlap; every object fully visible; consistent relative scale; clean cuttable arrangement

[BACKGROUND]
plain neutral background; no floor plane; no environment; no room; no walls

[RESTRICTIONS]
no characters; no text; no labels; no watermark; no perspective; no isometric; no ground shadows; no noise; no grime; no cracked or worn texture
```

**0 透视纯顶视**时，把 CAMERA 换成：

```text
[CAMERA]
strict top-down orthographic view; zero perspective; 90-degree overhead camera; top face only; parallel edges; no vanishing point; no front face; no side face; not isometric; not three-quarter view; not elevated view
```

**约 20° 轻俯视：**把上面的 CAMERA 和 RESTRICTIONS 换成：

```text
[CAMERA]
20-35 degree gentle elevated view, about 20 degrees, weak perspective, near-orthographic projection, slightly visible floor surfaces and furniture tops, not front view, not pure top-down, not 45-degree isometric view

[RESTRICTIONS]
no characters; no text; no labels; no watermark; no dramatic perspective; no ground shadows; no noise; no grime; no cracked or worn texture
```

### 0.4 生成前四问

1. 这一批是 0 透视，还是约 20°？0 透视再确认是纯顶视还是带正面。同一批不要混。
2. 这批属于哪一个尺寸等级（XS / S / M / L / XL / 建筑）？最终像素先写下来。
3. 是否只有一个类别、8–12 件、彼此不接触、没有地面和地面影？
4. 缩小到游戏尺寸后，轮廓是否仍能一眼认出用途？

## 1. 这套方法在解决什么

目标不是生成一张好看的概念图，而是一条能持续生产、能拆开、能组合、能进 Godot / Unity 的资产线。

AI 负责设计和生产积木。引擎负责搭积木。

一张完整场景图通常把镜头、光照、家具、道具和背景焊在一起，不能复用。常见失败：

| 问题 | 进项目后会发生什么 |
| --- | --- |
| 风格与描边漂移 | 下一批变成另一种像素密度、材质和轮廓 |
| 视角与比例失控 | 桌、柜、灯、人来自不同镜头，没有同一把尺子 |
| 场景无法拆分 | 墙、柜台、道具、地板焊在一张图里 |
| 尺寸与阴影随机 | 进引擎后反复改 Scale；自带地面投影和游戏灯光冲突 |
| 无法持续扩展 | 做完一个房间后，新家具和新地图不稳定 |

一张图能不能进引擎，用这五问体检。多数是否定的，它就是概念图，不是资产：

1. 图里的物体能否拆成独立资产？
2. 能否与下一批保持同一风格、同一镜头、同一比例？
3. 放入 Godot 或 Unity 后，能否尽量保持 Scale = 1？
4. 不同资产能否自由组合，搭出不止一个场景？
5. 扩展新地图时，能否沿用同一套规则继续生产？

生产链：

```text
主题 → Visual Bible → Master Scene → 资产拆分 → 分类 Sheet → PNG → 引擎场景
```

| 失控点 | 用什么锁住 |
| --- | --- |
| 风格漂移 | Visual Bible：色板、描边、细节密度、干净型高清像素 |
| 视角漂移 | 同一批只锁一种镜头：0 透视或约 20° |
| 比例混乱 | 角色参照 + 64px 基准单位 |
| 资产不可复用 | 拆分表 + 分类 Production Sheet |
| 生成后难交付 | 命名、尺寸、图层、透明背景、引擎验证 |

## 2. 十步生产线

每一步都要留下交付物。下一步只处理自己的问题。

| 步 | 做什么 | 交付物 |
| --- | --- | --- |
| 01 Theme | 世界观、空间功能、扩展方向 | Theme Brief |
| 02 Visual Bible | 风格、镜头、色板、光照、禁用项 | 视觉规则板 |
| 03 Master Scene | 用一个小空间验证规则 | 样板间 |
| 04 Asset Breakdown | 把样板间拆成可独立生产的对象 | 资产清单 |
| 05 Production Sheet | 按类别生成同类资产 | 分类 Sheet |
| 06 Asset Cutter | 切出边界完整的单独对象 | 透明 PNG 初稿 |
| 07 Normalizer | 统一尺寸、留白、底部锚点、命名 | 标准化 PNG |
| 08 Asset Library | 归档、预览、说明、检索 | 素材库 |
| 09 Engine Build | 在引擎里按层组合并验证 | 示例场景 |
| 10 Expansion | 复用已有模块，只补独有资产 | 新地图 |

### Theme Brief 最少要回答

| 问题 | 阴都职场示例 |
| --- | --- |
| 这是怎样的世界？ | 阴间有一套行政化办事系统 |
| 这里被谁、用来做什么？ | 登记、排队、审批、归档、发放凭证 |
| 希望玩家感到什么？ | 压迫、荒诞、秩序感、轻微幽默 |
| 画面由什么构成？ | 炭黑石材、胡桃木、黄铜、纸张、克制玉绿 |
| 下一张地图能做哪里？ | 档案室、桥梁管理处、医院、审批大厅 |

错误流程：先生成「阴都办事大厅 / 赛博酒馆 / 古风书院」整张氛围图，再往外抠桌子。边界不干净，比例无法统一，下一张也复现不了规则。

正确顺序：先用小样板间确认规则 → 拆成建筑、家具、功能道具、光效 → 按类别生产 → 引擎组合。不要在规则没锁定前攒素材。

## 3. 资产怎么拆

积木不是「看起来像一个物体的图」，而是有类别、边界、比例和命名，能单独摆放、单独替换的单元。能独立摆放、替换、复用的，就做成独立资产。只服务一件东西的微小细节，不必拆。

| 类别 | 典型内容 | 职责 |
| --- | --- | --- |
| 建筑件 | 墙体、墙角、门洞、栏杆、立柱、地面、台阶 | 空间边界和拼接 |
| 家具 | 桌子、椅子、柜子、书架、推车 | 空间功能，可反复摆放 |
| 功能道具 | 印章台、算盘、打印机、终端、文件箱 | 任务、交互、世界观信息 |
| 装饰道具 | 纸张、笔筒、墨水瓶、盆栽、指示牌 | 生活感，不改变主功能 |
| 光效 | 台灯、青灯、火焰、提示光、烟雾 | 独立控制氛围，不烘死在底图里 |

阴都职场的 10 张基础 Sheet（换题材时改清单，不改「一类一张」）：

| Sheet | 优先包含 | 目的 |
| --- | --- | --- |
| 01 建筑模块 | 墙段、门洞、地板、台阶、栏杆 | 可拼接的空间骨架 |
| 02 办公桌 / 柜台 | 办事桌、前台、审讯桌、登记台 | 主家具和工作区 |
| 03 柜子 / 书架 | 档案柜、矮柜、文件架、卷宗架 | 垂直收纳 |
| 04 椅子 | 木椅、软椅、等候椅、会议椅 | 和角色、桌面的互动 |
| 05 办公设备 | 终端、打印设备、排号机、投递箱 | 职场系统和玩法接口 |
| 06 小型 Props | 印章、卷宗、笔筒、茶具、冥钱 | 桌面和角落的小素材 |
| 07 灯具 | 壁灯、落地灯、台灯、引魂灯 | 光源本体可替换 |
| 08 装饰物 | 公告板、卷轴、绿植、指示牌 | 叙事，不承担结构 |
| 09 地板 / 墙面 | 地砖、墙板、门牌、边角 | 扩展时墙地系统统一 |
| 10 FX | 冥火、屏幕微光、轻烟、粒子 | 叠加气氛，不污染本体 |

同一张 Sheet 内锁四件事：镜头一致、色板一致、尺寸等级一致、材质一致。变化只发生在功能和轮廓细节。小物件另开 Sheet，不要把主家具缩小来迁就道具。

从样板间到素材库：

1. 只圈一个家族，例如「办事桌 / 柜台」，不要把墙、地板、椅子、灯一起带进来。
2. 写明数量、同类功能、固定镜头、统一色板、间距、禁止混类。
3. 只留轮廓完整、镜头稳定、尺寸合理的；不合格直接淘汰。
4. 统一文件名，放回 Master Scene 复核。

Sheet 提交前：

- 不看标题也能感到它们是同一个功能家族。
- 每件都有完整边缘和足够留白，没有和别的物件、底座或阴影黏连。
- 镜头、色板、轮廓、尺寸能对上 Master Scene。
- 至少有主款和有意义的同类变体。

可拆性检查：

1. 墙、门、桌、柜、灯、文件、地面能否被清楚分开？
2. 是否全部来自同一种镜头？
3. 桌椅、柜体、门洞、角色参照放在一起是否合理？
4. 换一张桌子，房间是否还成立？
5. 新房间能否复用现有资产约 60% 以上？不能的话，回头检查分类和规则。

建筑模块优先保证边界，再追求气氛。墙、门洞、地板、台阶要能横竖拼接，不依赖透视收缩。

FX 可以分层，但不能吞没资产。顺序是：灯具本体 → 局部功能发光 → 独立环境烟气。去掉 FX 后，灯具本身仍然完整。

## 4. Visual Bible

Visual Bible 不是「赛博、国风、像素风」几个形容词。Prompt 和资产类别可以变，Visual Bible 不该频繁变。

「像素风」会跑成低分辨率复古、颗粒旧化、网点或重噪点。本方案统一用 **干净型高清像素感**：可切割、可缩放、可复用。

### 六项规则

| 项 | 锁什么 |
| --- | --- |
| 视觉风格 | 大色块、低纹理、清晰轮廓、中低细节、柔和明暗 |
| 镜头 | 这一批只选一种：0 透视俯视，或约 20° 轻俯视。见第 0 节 |
| 色板 | 每种颜色有职责，不是多堆几个好看的颜色 |
| 轮廓与细节 | 外轮廓清楚，内部结构简化；小尺寸仍可读 |
| 光照与阴影 | 柔和光向；只留自身结构暗部；环境投影交给引擎 |
| 比例与边界 | 用角色、门洞、家具建立共同尺度 |

要保留：大色块、低纹理、清晰轮廓、中低细节、柔和明暗、干净表面、可读性优先。

要禁止：颗粒、噪点、旧化、脏污、磨损、裂纹、网点、抖动纹理、重度纸张纤维、过度锈蚀、模糊边缘。

验收：缩小后是否仍能一眼认出？如果去掉一半内部纹理反而更清楚，说明细节过多。

### 阴都职场色板（换题材时整表替换，不要逐张发明）

| 角色 | 建议颜色 | 用在哪 |
| --- | --- | --- |
| 主结构色 | 炭黑、深灰 | 石材墙体、地面、建筑边界 |
| 家具主色 | 胡桃木棕 | 桌子、柜台、柜体、书架 |
| 金属点缀 | 哑光黄铜 | 把手、边角、灯具、机械结构 |
| 信息色 | 米白、纸张灰褐 | 文件、表单、标签、书页 |
| 超自然点缀 | 克制玉绿 | 冥火、屏幕、特殊灯光 |

同一 Sheet 的简写：深炭黑、暖深木、古铜黄、纸张米白、克制玉绿。颜色负责分层，不负责堆装饰。

### 原指南的 Prompt 骨架（20–35°，案例原句）

```text
[STYLE]
clean high-definition pixel-art game art, large color blocks, low texture, crisp dark outlines,
medium-low detail, soft clean lighting, readable silhouette, smooth controlled surfaces

[CAMERA]
20-35 degree gentle elevated view, weak perspective, near-orthographic projection, slightly visible
floor surfaces and furniture tops, not front view, not 45-degree isometric view

[PALETTE]
charcoal structure, walnut wood furniture, muted brass details, parchment paper accents, restrained
jade green glow

[LIGHTING]
soft upper-left lighting, subtle contact shading, no cast ground shadows, no dramatic shadows

[RESTRICTIONS]
no grain, no noise, no weathering, no distressed effect, no scratches, no cracks, no dirt, no speckles,
no dithering, no grunge, no heavy texture, no text, no labels, no logo, no watermark
```

这一批若是约 20°，用上面的 CAMERA。若是 0 透视，改用第 0.3 节的 CAMERA。STYLE、PALETTE、RESTRICTIONS 可以沿用。LIGHTING 里的 “subtle contact shading” 与后文「禁止脚下接触影」冲突，以阴影一节为准：不要接触影、不要地面椭圆影。

## 5. 镜头

资产能不能拼在一起，取决于它们是否来自同一个镜头，而不是每一张是否好看。新资产无法自然放进主场景，即使单独精致，也不入库。

### 约 20° 这一批（原指南）

下面的「禁止纯俯视」只约束这一套镜头。改做 0 透视时不要套用这一条，改用第 0 节。

| 项目 | 固定规则 | 目的 |
| --- | --- | --- |
| 视角 | 约 20–35° 轻俯视 | 看见少量顶面和地面，同时保留正面 |
| 透视 | 弱透视、近似正交 | 减小近大远小，方便并排和拼接 |
| 画面 | 正面清楚、侧面克制、落地明确 | 共享空间尺度 |
| 禁止 | 完全正视、纯俯视、45° 等距、强透视 | 避免组合后冲突 |

三种不要落入的镜头：

| 方向 | 问题 |
| --- | --- |
| 完全正视 | 看不到桌面、地面和顶面，占地难判断 |
| 45° 等距 | 顶面和侧面比重变了，依赖等距网格；本项目不是等距 |
| 电影感强透视 | 近大远小过强，同类资产尺寸和边界失真 |

负向词：`cinematic wide angle, dramatic perspective, extreme perspective, fisheye lens, low-angle shot, strong depth of field, dynamic foreshortening`

正向词：`weak perspective, near-orthographic projection, minimal perspective distortion, consistent game-building perspective`

原指南 CAMERA 模块：

```text
20-35 degree gentle elevated view,
weak perspective,
near-orthographic projection,
consistent game-building perspective,
slightly visible floor surfaces,
visible furniture tops,
minimal perspective distortion,
not front view,
not 45-degree isometric view,
not cinematic wide angle,
not fisheye
```

原指南 PERSPECTIVE 模块：

```text
weak perspective,
near-orthographic projection,
minimal perspective distortion,
consistent game-building perspective,
stable asset scale,
slightly visible floor surfaces,
clear front-facing structure,
subtle side planes,
not cinematic wide angle,
not fisheye,
not extreme perspective,
not dramatic foreshortening
```

生成后三项检查（轻俯视）：顶面可见比例接近主场景；正面是主信息、侧面只提示厚度；脚部或墙根接地，地面露出量和主场景一致。镜头错了不要用裁切掩盖。不匹配时只改镜头描述：俯视角度、透视强度、顶面可见量、地面关系。

强透视会让同款桌子前后尺寸差太大，墙地边线向消失点收缩，裁切后无法对齐。远处桌子应约等于近处桌子。

概念图氛围好但不能用时：删掉 wide angle / dramatic perspective / fisheye / low-angle；写入弱透视；删掉深长走廊、远景、夸张光束、强景深和大面积投影；先让单体合格，再放回 Master Scene。

### 这一批若是 0 透视

用第 0 节的 CAMERA，不要和约 20° 混在同一张 Sheet。生成后改成检查：

1. 是否正交：平行边有没有往远处收拢？
2. 顶面 / 正面的比例是否和样板间一样（纯顶视则检查是否露了不该有的正面）？
3. 同款物件放在画面前后，占地是否仍是同一套像素尺寸？
4. 去掉环境后，能否作为独立 PNG 放进另一个场景，而不带着镜头拉伸？

## 6. Production Sheet 的标准 Prompt

七个区块。风格、镜头、光照、禁止项来自 Visual Bible，不随类别改变。唯一变量是 `[ASSETS]`。要提高可读性时，先改数量或间距，不要同时改镜头和风格。

| 区块 | 固定内容 | 控制什么 |
| --- | --- | --- |
| STYLE | 干净高清像素、大色块、低纹理、深色轮廓、中低细节、柔和明暗 | 视觉语言和细节密度 |
| CAMERA | 这一批一种镜头：0 透视用第 0.3 节，约 20° 用本节模板 | 空间关系 |
| LIGHTING | 柔和明暗；只留结构暗面；无地面影 | 体积，同时避免预烘焙光向 |
| ASSETS | 8–12 件同一类别 | 这张 Sheet 生产什么 |
| LAYOUT | 隔离、间距大、不接触、不重叠、完整可见、相对比例一致 | 能否切图 |
| BACKGROUND | 纯净中性背景，无地面、无场景 | 去底和透明边 |
| RESTRICTIONS | 无人物、文字、标签、环境、戏剧透视、投影、噪点旧化 | 排除常见污染 |

原指南可复制模板（20–35°）：

```text
[STYLE]
clean high-resolution pixel-inspired 2D game assets; large color blocks; low texture; clean dark brown outlines; clear readable silhouettes; controlled medium-low detail density; soft value transitions; no grain or weathering

[CAMERA]
20-35 degree gentle top-down view; weak perspective; near-orthographic projection; never front view; never 45-degree isometric view

[LIGHTING]
soft upper-left lighting; keep only internal structural shading and self-occlusion; no cast ground shadows; no environmental shadows

[ASSETS]
8-12 isolated assets from one category: [REPLACE THIS LIST ONLY]

[LAYOUT]
isolated objects; generous spacing; no touching; no overlap; every object fully visible; consistent relative scale; clean cuttable arrangement

[BACKGROUND]
plain neutral background; no floor plane; no environment

[RESTRICTIONS]
no characters; no text; no labels; no watermark; no dramatic perspective; no ground shadows; no noise; no grime; no cracked or worn texture
```

替换示例：`desk lamp, pen cup, stamp box, book stack, document tray, calculator, small terminal, binder, paper cart`

中文数量约束（镜头句按这一批替换；下面是约 20° 的写法）：

```text
资产类别：阴都行政机构的办公桌与柜台，8-12 个同类变体
镜头：约 20-35° 轻俯视，弱透视，近似正交
质量：干净型高清像素感；大色块、低纹理、清晰轮廓、中低细节、柔和明暗
排布：独立物件，均匀大间距，无接触、无重叠，完整可见，保留裁切余量
背景：纯净中性背景，不含场景、人物、文字、标签或地面投影
禁止：颗粒、旧化、脏污、裂纹、强透视、45° 等距、完全正视、环境阴影
```

批量顺序：

1. 把七个区块存成唯一母版，写上版本日期。
2. 先用 6–8 件同类做小样，不要一开始生成全部分类。
3. 确认模型、Prompt、图片比例和参考图，通过后冻结为项目默认。
4. 下一批只改 ASSETS，例如从「桌面用品」改为「档案柜配件」。
5. 验收能否逐件拆分、有没有地面影、比例是否对。不合格只回改对应区块。

合格 Sheet：同一类别；镜头没有混入第二种；彼此分开、不遮挡、不切边；大色块低纹理；没有人物、文字、标签、场景和地面影。

## 7. Master Scene（样板间）

样板间不是最终地图，也不是「最好看的那张场景」。它用最少元素把规则验证清楚，是后续所有 Sheet 的唯一视觉裁判。不要先生成几百个道具。

它同时是：概念（空间、情绪、材料、功能）、风格指南（镜头、色彩、比例、光照、轮廓）、生产基准（新资产必须和它并排复核）。

必须先固定：

| 维度 | 内容 |
| --- | --- |
| 建筑语言 | 主墙、立柱、门洞、地面、台阶、窗格、分隔结构 |
| 镜头 | 这一批选定的那一种：0 透视，或约 20–35° 轻俯视 |
| 色彩与材质 | 炭黑结构、深胡桃木、哑光黄铜、纸张米白、克制玉绿 |
| 比例 | 角色、门洞、桌、柜、椅子、终端在同一尺度 |
| 轮廓与光源 | 清晰深色描边、低纹理、柔和主光；不靠颗粒、旧化、浓雾或长投影制造氛围 |

样板间通过之前，你要能说清：镜头是哪一种、主色有哪些、桌子和柜子的比例、轮廓有多重、灯效如何独立处理。说不清的地方，就是下一批会漂的地方。

没有主场景就量产，会出现三种失控：风格各自偏古董 / 蒸汽朋克 / 科幻 / 恐怖；没有门洞和角色参照时柜子像玩具；顶面和侧面在不同批次轻微漂移。

生产顺序：主场景固定镜头 → 新资产在旁边验收角度、比例、落地、风格 → 再切图、去背、命名、标准化、入库。不以某一张局部素材当临时标准。

样板间要能拆成建筑、家具、道具、设备、光源。透视角、雾气和投影会让资产粘连，这种图不能当母版。

## 8. 一张 Sheet 放多少

展示图和生产图不是同一种文件。

| 类型 | 怎么做 | 不要做什么 |
| --- | --- | --- |
| 展示图 | 可放 20–30 件，用于封面、海报、预览 | 不要直接当单件母图 |
| Production Sheet | 同类 8–12 件，完整轮廓、固定镜头、裁切间距 | 不要用无关物品填空，不要混小物、家具、建筑、特效 |
| 补充 Sheet | 超容量就拆成 A/B/C，例如桌柜 A、桌柜 B | 不要为了「一张全收录」牺牲尺寸 |

同一张约 2048px 画布：

| 数量 | 单件大约能分到 | 判断 |
| --- | --- | --- |
| 20–30 件 | 约 150–250px | 只适合展示拼贴 |
| 8–12 件 | 约 350–550px | 常规生产页 |
| 1–4 件 | 更高 | 复杂设备、英雄资产 |

按复杂度调整，8–12 不是死规定：

| 资产 | 建议数量 |
| --- | --- |
| 建筑模块 / 大型柜台 | 4–8 |
| 桌子、柜子、设备 | 8–12 |
| 椅子、灯具、装饰 | 10–14 |
| 小型 Props | 12–16，一开始黏连或看不清就拆 |
| Hero / 复杂机关 | 1–4 |

第三部分里还有一版更紧的建议：建筑 6–10，桌与坐具 6–10，柜架 6–8，功能设备 6–10，纸张笔筒灯具装饰与 FX 8–12。和上表冲突时，以「缩小后仍能认出、轮廓不黏连」为准，宁少勿挤。

拆分信号：

1. 两个资产的暗轮廓、外沿或投影会被误判成一体。
2. 缩小到接近游戏尺寸后，分不清是桌、柜、灯还是设备。
3. 开始用颗粒、划痕、脏污假装细节。

留白要求：每件四周有干净背景；同类之间有稳定空隙；只留物体自身结构暗面；不要墙、地板、人物、文字、无法分离的气氛层。

开一张新生产页的顺序：锁定单一类别和尺寸等级 → 复杂的少放 → 从约 8 件试 → 不合格就拆成 A/B → 切完放回 Master Scene。

## 9. 尺寸体系

64px 不是强制 Tile，而是 Scale Reference。资产不必都是 64 的整数倍。同一项目里的相对关系必须稳定。

### 游戏最终显示尺寸

AI 不要直接生成这些小尺寸。先做大母版，再切、再缩小。

| 等级 | 最终尺寸 | 典型资产 |
| --- | --- | --- |
| XS | 24–32px | 印章、纸页、杯子、单个小道具 |
| S | 40–64px | 笔筒、香炉、台灯、文件盒 |
| M | 64–128px | 椅子、小桌、终端、矮柜 |
| L | 128–192px | 办公桌、前台、文件柜、会议桌 |
| XL | 192–384px | 大型柜台、机关、入口装置 |
| 建筑组件 | 300–800px | 墙段、门洞、窗体、地板组块 |

第三部分的 XL 写法是「大型设备、门洞、建筑件 192–384px」，和第 11 部分的建筑组件 300–800px 不完全相同。门洞、墙段用更大的建筑区间；普通大型家具停在 XL。

先问它在游戏里承担什么阅读任务。既要玩法信息又要当主视觉，就升一级。只是补氛围，就保持小而清晰。

### 角色尺子（原指南，轻俯视画面）

1920×1080 画面里，普通成年人最终显示高度 170–190px，第一版基准 **180px**。这张角色图不必是最终角色美术，职责是比例尺：固定视角、中性站姿、固定身高、标明地面基线。怪物、儿童、巨人另建对照，不要混用。

| 资产 | 建议最终尺寸 | 和 180px 角色的关系 |
| --- | --- | --- |
| 普通成年人 | 180px 高 | 世界基准，脚底对齐基线 |
| 办公桌 | 150–180px 宽 | 桌面约在腰部，不能压过入口 |
| 办公椅 | 60–80px 高 | 低于腰部，坐和站都可读 |
| 文件柜 | 100–150px 高 | 约胸部到头部 |
| 垃圾桶 | 50–70px | 明显小于膝或腰，不能和椅子、柜子同体量 |
| 号码机 / 终端 | 80–110px 高 | 约半身到胸口 |
| 窗口 / 门洞 | 180–220px 高 | 高于角色，能解释通过 |

比例错误时的修正：

- 人站在桌边只到桌腿，或桌面远高于腰：先改桌子的尺寸等级，再复核椅子和桌面道具。不要只把角色放大。
- 人比文件柜和终端小得多：降低柜体 / 终端输出尺寸，或明确它们是 XL 而不是普通家具。
- 门洞解释不了通行：用角色高度反推建筑组件。

约 20° 这一批按上表的画面高度来读。0 透视这一批不要把「高」直接当成画面高度，改成占地对照，见第 0.1 节。底边对齐两边都有效：角色落点、家具外轮廓、门洞地面落在同一条基线上。

### 母版尺寸 ≠ 游戏尺寸

永远先大后小。缩小会收敛瑕疵；从小图放大会把模糊、断线和错误纹理一起放大。

以最终宽约 160px 的办公桌为例：

| 阶段 | 尺寸 | 检查 |
| --- | --- | --- |
| 生成母版 | 400–600px，常用 512px | 桌面厚度、抽屉、金属边、主轮廓、留白够不够切 |
| 清理 | 仍用母版 | 去背景和投影，修杂点，统一底边和锚点 |
| 缩小输出 | 160px | 外轮廓和关键功能是否仍可读 |
| 引擎 | Scale = 1 | 和人物、椅子、文件柜是否仍像一套 |

工作区间（可按复杂度加大母版）：

| 游戏最终尺寸 | 建议母版 | 适合 |
| --- | --- | --- |
| 24–32px | 128–256px | 小道具、按钮、极小拾取物 |
| 40–64px | 192–320px | 杯子、台灯、桌面工具 |
| 64–128px | 256–512px | 椅子、终端、小型设备 |
| 128–192px | 400–768px | 办公桌、文件柜、功能装置 |
| 192–384px | 512–1024px | 大型设备、门洞、建筑模块 |

可放进生成指令的尺寸句（镜头按项目替换）：

```text
先生成 400-600px 的干净单件高清母版；最终将下采样为 160px 游戏资产。画面采用指定镜头；大色块、低纹理、清晰轮廓、中低细节、柔和明暗；禁止颗粒、旧化、噪点、脏污、重纹理和地面投影。
```

从母版到 PNG：

1. 单件、干净背景、足够留白、指定镜头。
2. 选结构最完整的一张，删掉附属物，只留可复用主体。
3. 去掉投影、噪点、颗粒旧化和杂乱高光；保留柔和明暗和必要结构边界。
4. 底边对齐项目基线，同类留白一致。
5. 缩小到最终尺寸，导出透明 PNG。不再放大。
6. 和人物、主家具、门洞一起放进 Master Scene。

开始新资产前：

1. 它属于哪个尺寸等级？
2. 它和哪个基准对象比较（角色、桌子、柜子、门洞）？
3. 最终 PNG 的目标区间是多少？
4. 它能否以 Scale = 1 进场景？不能就改素材尺寸或锚点。

引擎里的例子（最终文件已经是目标像素）：

| 文件 | 像素 | 引擎 |
| --- | --- | --- |
| desk_01.png | 160 × 96 | Scale = 1 |
| cabinet_01.png | 112 × 160 | Scale = 1 |
| chair_01.png | 68 × 82 | Scale = 1 |

生成前在 Sheet 里写下目标，例如桌子 160×96、文件柜 112×160。

## 10. 阴影

Asset Sheet 不生成地面投影。光照在最终场景里统一发生。

| 暗部 | 是否保留 | 常见位置 |
| --- | --- | --- |
| 家具内部暗面 | 保留 | 桌底内侧、抽屉缝、柜体侧面、设备凹槽 |
| 自身遮挡 | 保留 | 桌面与支架交界、把手下方、门缝 |
| 地面椭圆阴影 / 接触影 | 去掉 | 椅脚、柜脚、道具底部 |
| 长方向投影 | 去掉 | 桌子右下方、窗光方向、人物脚下 |
| 环境投影 | 去掉 | 墙角压暗、地面反射、窗格影 |

判断：把背景和地面想成删掉。暗部仍然是物体结构的一部分就留；它需要某块地面或某个光源才成立，就从 Sheet 里去掉。

缩小后看不清时，改大色块、轮廓和结构分区，不要用更重的地面影补轮廓。导出前在浅色和深色背景上各看一次透明边。

运行时三层，Sheet 不预烘焙：

| 层 | 解决什么 | Sheet 提供什么 |
| --- | --- | --- |
| Character Shadow | 角色落地、移动、遮挡 | 角色轮廓干净，无固定脚下阴影 |
| Furniture Shadow | 家具和当前地面的接触 | 底边和透明边规范，方便落地 |
| Environment Lighting | 房间亮暗、时间、主光方向 | 无环境投影、无固定场景反光 |

可直接加入的阴影句：

```text
保留家具内部暗面、桌底暗部、柜体结构阴影与自身遮挡；禁止地面椭圆阴影、长方向投影、环境投影、地面反射和脚下接触影。资产使用干净背景与透明边，最终由游戏统一生成 Character Shadow、Furniture Shadow 和 Environment Lighting。
```

## 11. 切图、标准化、命名

展示用的拼贴不能直接丢进切图工具。工具擅长：背景干净、对象分离、轮廓完整的 Production Sheet。粘连、人物、阴影残留要回到生成阶段改，不要指望工具修。

### 切图管线（Asset Cutter）

1. 读入验收过的同类 Sheet，只有单件资产和中性背景。
2. 识别主背景色或容差，得到前景遮罩。
3. 按像素连通区域找候选，候选还不是最终文件。
4. 用最小面积、长宽比、位置排除噪点、装饰线、边缘碎片。
5. 按统一留白扩展裁切框，去背，输出带透明通道的 PNG。
6. 按类别加序号命名，写下来源 Sheet、裁切坐标、复核状态。

能自动切的条件：对象之间有明显空隙；完整可见、四周有裁切空间；纯净中性背景、不带地面影；同类尺度和方向稳定。

会切失败：桌椅相连、道具重叠、互相遮挡；主体贴边或被装饰框压住；地面渐变、环境纹理、椭圆影、长投影；混入人物、场景、不同镜头或异常超大物体。

DOCX 对「给工具处理的图片」的要求（和上面一致，执行时以这张表为准）：

| 项目 | 推荐标准 |
| --- | --- |
| 背景 | 单一纯色；最好透明，或纯白、米白；无渐变、纹理、投影 |
| 素材之间 | 不接触、不重叠，至少留 12–24 px 空白 |
| 单个素材 | 轮廓完整，不被其他物件遮挡 |
| 阴影 | 尽量不要大面积柔和投影；有也不能连到别的物件 |
| 文字 | 最好放在素材下方，且与素材留出间隔 |
| 尺寸标注 | 放在名称下方，如「长椅 / 128×64」，不要压到素材上 |
| 画面内容 | 不要共同地面、房间墙体、整体边框、复杂装饰背景 |

工具本身：解压 `GameAssetBatchTool-Windows-x64.zip` 后使用。

### 导出规范

| 输出 | 规则 | 示例 |
| --- | --- | --- |
| 文件名 | 类别 + 两位序号；小写英文和下划线 | `desk_01.png`、`cabinet_02.png`、`terminal_01.png` |
| 透明背景 | RGBA；四周无灰雾、残影、半透明脏边 | |
| 统一留白 | 按分类外扩；同类底边对齐 | 家具底边留同级透明边 |
| 锚点 | 底边基线或锚点坐标 | `anchor: bottom-center` |
| 最终尺寸 | 按下采样校验，引擎 Scale = 1 | `desk_01: 160 × 96` |
| 清单 | 来源 Sheet、裁切框、导出名、类别、人工状态 | `sheet_office_01 → desk_01` |

目录：

```text
source_sheets/   原始 Production Sheet
candidates/      Cutter 候选裁切
assets_png/      复核通过的透明 PNG
manifests/       文件名、尺寸、锚点、来源
```

入库顺序：先验收整张 Sheet → 跑 Cutter，不覆盖正式库 → 人工看合并、截断、边缘、锚点 → 只有通过的才进 `assets_png`。

### Normalizer（切完之后）

Cutter 回答「有几个对象、在哪里」。Normalizer 回答「在项目里该多大、留多少边、锚点在哪」。

等级示例：`chair = S`，`desk = M`，`cabinet = M`，`counter = L`，`building = XL`。

| 等级 | 典型 | 判断 |
| --- | --- | --- |
| S | 椅子、小设备、台灯、桌面道具 | 小型可交互，不和成人或主家具抢体量 |
| M | 办公桌、文件柜、终端 | 和角色、门洞关系一致 |
| L | 柜台、大型设备、服务台 | 功能核心，仍能解释角色交互 |
| XL | 建筑模块、门洞、外立面、大型装置 | 通行、房间边界或地标 |

注意：这里的 S/M/L/XL 和第九章像素分级的名称不完全一一对应。执行时以「最终像素区间 + 和角色的关系」为准，文件里写明这一件的目标宽高，不要只写一个字母。

管线：识别类别 → 读取目标宽高、边距、锚点 → 用质量够的母版下采样（不要把低清图放大）→ 补左右和上方留白，底边留白与同类一致 → 底边对齐基线，记录 bottom-center → 导出 RGBA，并更新清单。

单独统一宽高不够。透明边决定物体在画布里的位置，锚点决定放进场景后怎么落地。三项一起做，Scale 才能保持 1。

## 12. 引擎与场景分层

Scale = 1 指最终 PNG 进 Godot 或 Unity 后，节点保持默认 100% 缩放。大小和与角色的关系在导出前已经固定。

不要用引擎缩放掩盖生产问题：

| 看起来能用 | 实际问题 | 回到哪里 |
| --- | --- | --- |
| desk Scale = 0.43 | 原图过大，难和后续桌类对齐 | 最终 PNG 尺寸或裁切边界 |
| cabinet Scale = 1.72 | 原图过小，放大后轮廓变差 | 回到母版，重新下采样 |
| chair Scale = 0.61 | 和人物关系不对 | 尺寸体系和角色参照 |
| 每个场景单独调一遍 | 同一 PNG 表现不同 | 建立唯一最终规格 |

动画、镜头特效、明确设计的夸张变形可以改 Scale。关掉特效和动画后，静态资源如果仍必须非 1 才能摆对，源文件就还没做完。

导入检查：

- 导入前：文件名、透明背景、最终像素、裁切留白与 Sheet 一致。
- 导入后：放大缩小不意外发糊；全项目同一套像素显示策略。
- 节点 Scale 保持 1, 1。
- 基线可对齐；桌、柜、椅能解释同一个人的使用尺度。
- 同一资源换场景不必重新缩放。

若某张图必须改 Scale，记一笔：资产名、原因、正确最终尺寸、要重出的源图。不要直接存成例外。

场景不是一张 1920×1080 的 JPG。六层：

| 层 | 内容 | 生产责任 |
| --- | --- | --- |
| 05 FX / Light | 冥火、粒子、光晕、环境亮暗 | 运行时叠加，可随时间或交互变化 |
| 04 Characters | 角色、NPC、怪物 | 独立动画和移动，不烘焙进背景 |
| 03 Props | 算盘、文件、台灯、道具 | 单件 PNG，可拾取、替换、隐藏 |
| 02 Furniture | 桌子、柜台、椅子、设备 | 按尺寸体系摆放，Scale = 1 |
| 01 Architecture | 墙、门、窗、柱、固定结构 | 房间边界和遮挡 |
| 00 Floor | 石砖、地毯、地面模块 | 落点、导航、统一阴影 |

换桌子只替换 Furniture 里对应 PNG。换昼夜只动 FX / Light。角色可经过桌前、桌后和门洞，道具不要错误压在建筑层上。

交付场景时给：分层 PNG、排序说明、一个 Master Scene 示例。用户应能单独开关每一层。

## 13. 扩展新地图

扩展时优先复用已有模块，只补这个空间真正独有的约 10–20 个资产。

1. 复用：墙体、地面、桌椅、柜体、灯具、终端、文件等通用对象。
2. 补齐：只做独有功能，例如医疗床、桥梁窗口、特殊档案架。
3. 重组：仍在同一镜头、比例、色板和层级里摆放。
4. 反哺：新资产归档回库，让下一张地图的复用率继续上升。

同一套柜台、文件柜、灯具、墙体、地板、终端和装饰，可以组成档案室、审批大厅、管理处或其他区域。

## 14. 下次开做时的最短路径

1. 写 Theme Brief（世界观、谁在用、情绪、材质、下一张地图）。
2. 锁定 Visual Bible：干净像素、这一批的镜头（0 透视或约 20°，第 0 节）、一张色板、无地面影。
3. 做一张小 Master Scene，能说清镜头和比例后再批量。
4. 拆资产清单，一类一张 Sheet。
5. 用第 0.3 节模板，先 6–8 件小样，通过后只改 ASSETS。
6. 母版做大，切图，缩到最终像素，锚点 bottom-center，命名 `类别_序号.png`。
7. 和角色参照、主家具一起放进样板场景，Scale = 1。
8. 按六层搭场景。新地图只补独有资产。
